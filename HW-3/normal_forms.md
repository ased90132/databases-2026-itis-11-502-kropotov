# HW3 — Нормализация базы данных интернет-магазина

## 1. Исходное состояние базы данных

В предыдущей работе была создана база данных интернет-магазина,
состоящая из следующих таблиц:

- `category` — категории товаров;
- `product` — товары;
- `client` — клиенты;
- `orders` — заказы;
- `order_product` — состав заказов;
- `delivery` — доставки;
- `payment` — платежи.

Исходная схема уже была нормализована: данные разных сущностей хранились
в отдельных таблицах, а связи между таблицами выполнялись с помощью
первичных и внешних ключей.

Поэтому для демонстрации процесса нормализации были временно добавлены
две избыточные структуры, содержащие ошибки.

---

## 2. Первая добавленная ошибка — дублирование данных клиента

### Изменение структуры

В таблицу `orders` были временно добавлены следующие атрибуты:

```text
client_first_name_bad
client_surname_bad
client_email_bad
```

После этого часть таблицы `orders` выглядела следующим образом:

```text
orders(
    order_id,
    order_date,
    status,
    order_total,
    client_id,
    client_first_name_bad,
    client_surname_bad,
    client_email_bad
)
```

При этом данные клиента уже хранятся в таблице `client`.

### Функциональные зависимости

Для таблицы `orders` существуют зависимости:

```text
order_id -> order_date, status, order_total, client_id
client_id -> first_name, surname, email
```

Поэтому возникает транзитивная зависимость:

```text
order_id -> client_id -> client_data
```

Дополнительные поля в `orders` дублируют данные из таблицы `client`.

### Возникающие аномалии

#### Аномалия обновления

Если клиент изменит email, его необходимо изменить в таблице `client`
и во всех заказах этого клиента. Если один заказ не обновить, в базе
появятся противоречивые данные.

#### Аномалия вставки

Данные клиента оказываются связаны с заказом. Если хранить клиента
только в `orders`, невозможно добавить клиента, у которого ещё нет заказа.

#### Аномалия удаления

Если удалить последний заказ клиента, можно потерять данные клиента,
если они хранятся только в таблице заказов.

### Исправление

Избыточные атрибуты были удалены из `orders`.

В нормальной структуре таблицы выглядят так:

```text
client(
    client_id,
    first_name,
    surname,
    email,
    phone_number,
    registration_date
)

orders(
    order_id,
    order_date,
    status,
    order_total,
    client_id
)
```

Таблица `orders` хранит только внешний ключ `client_id`, а все данные
клиента хранятся в таблице `client`.

Таким образом, каждый факт хранится только в одном месте, а связь между
клиентом и заказом реализуется внешним ключом.

## 3. Вторая добавленная ошибка — дублирование данных товара

### Изменение структуры

В таблицу `order_product` были временно добавлены следующие атрибуты:

```text
product_name_bad
category_name_bad
```

После этого часть таблицы `order_product` выглядела следующим образом:

```text
order_product(
    order_id,
    product_id,
    quantity,
    product_name_bad,
    category_name_bad
)
```

При этом название товара уже хранится в `product`, а название категории
хранится в `category`.

### Функциональные зависимости

Для таблицы `order_product` используется составной ключ:

```text
(order_id, product_id)
```

Основная зависимость:

```text
(order_id, product_id) -> quantity
```

Однако дополнительные поля зависят только от `product_id`:

```text
product_id -> product_name
product_id -> category_id
category_id -> category_name
```

Получаются:

- частичная зависимость `product_id -> product_name`;
- транзитивная зависимость
  `product_id -> category_id -> category_name`.

Следовательно, таблица нарушает требования 2НФ и 3НФ.

### Возникающие аномалии

#### Аномалия обновления

Если товар переименовать, его название нужно изменить во всех строках
`order_product`, где этот товар встречается. Если хотя бы одна строка
останется без изменений, названия товара будут различаться.

#### Аномалия вставки

Нельзя сохранить новый товар или категорию в таблице `order_product`,
пока товар не добавлен хотя бы в один заказ.

#### Аномалия удаления

Если удалить последний заказ, содержащий определённый товар, можно
потерять данные о товаре или категории, если они хранятся только
в `order_product`.

### Исправление

Избыточные атрибуты были удалены из `order_product`.

Нормальная структура:

```text
product(
    product_id,
    product_name,
    price,
    stock_quantity,
    category_id,
    brand
)

category(
    category_id,
    category_name,
    description
)

order_product(
    order_id,
    product_id,
    quantity
)
```

Таблица `order_product` содержит только данные, относящиеся к конкретному
товару в конкретном заказе: идентификаторы заказа и товара, а также
количество товара.

Название товара хранится в `product`, а название категории — в `category`.
